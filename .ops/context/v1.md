# Schema Lens Development Charter

## Product domain
Schema Lens simulates Solr schema and query behavior changes before production rollout.
The project prioritizes deterministic analysis, reproducible artifacts, and CI-safe quality gates.

## Architecture constraints
- Python 3.11+ project with package entry point `schema-lens`.
- Primary source code is under `schema_lens/`.
- Tests under `tests/`.
- Example workflows and configs under `examples/`.

## Coding standards
- Keep edits minimal and isolated to the task objective.
- Preserve existing style and naming conventions.
- Prefer deterministic behavior over heuristic side effects.
- Avoid introducing destructive shell operations.

## Testing expectations
- Always run configured install/lint/test commands from `.ops/config.yml`.
- Use non-integration tests by default.
- If task requires Docker-backed checks, clearly report and gate accordingly.

## Operational constraints
- No direct push to `main`; all changes go through PR.
- Respect branch naming `ops/<issue>-<runid>`.
- Do not modify secret values or external infra state.
